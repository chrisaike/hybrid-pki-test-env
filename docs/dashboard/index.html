Hybrid PKI Test & Certification Environment

A production-representative, multi-cloud-capable PKI test bed delivered as Infrastructure as Code — built to de-risk high-impact root, crypto, cloud, workload, and trust changes before they reach production. This dashboard visualizes what was built and the step-by-step process behind it.

What "hybrid" means here

Deployment on-prem-style services (CA, AD/GPO, SoftHSM) + cloud
Cloud multi-cloud (AWS implemented; Azure/GCP via same contracts)
Crypto classical (RSA/ECDSA/Ed25519) with a documented PQC path

Why it's Priority 1

Decreases risk of failed deployments and cuts the cost of an on-prem test environment. Prevents Production from becoming the first realistic integration test for high-risk changes, and provides a reusable certification service for updates, migrations, integrations, OEM products, and rollback plans.

Multi-cloud design

Each Terraform module exposes a cloud-agnostic contract (identical variables/outputs); the body is cloud-specific. Switching cloud = changing one source = line.

AWS implemented (ECS Fargate + ALB, ≥2 replicas); Azure/GCP are contract-complete stubs with a documented resource map.

Crypto agility & PQC readiness

All key generation and signing flow through a single provider registry — the crypto-agility seam. Adding an algorithm (including post-quantum) is one registration; the CA/issuance/OCSP/CRL code is unchanged.

Proven end-to-end

An entirely Ed25519 hierarchy — a third algorithm family added purely by provider registration — builds, issues, validates to root, and runs OCSP + CRL in the automated test suite. That is the exact path a future ML-DSA (FIPS 204) change follows: register the provider, set key.type, re-run make certify.
